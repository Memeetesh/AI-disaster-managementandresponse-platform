# Deploying DRISHTI

Three free services:

| Piece | Host | Notes |
|---|---|---|
| Database (PostgreSQL + PostGIS) | **Supabase** | PostGIS ships enabled |
| Backend (FastAPI + SSE) | **Render** | long-lived process — needed for the realtime stream |
| Frontend (Next.js) | **Vercel** | native Next build |

The repo is already prepared: `render.yaml` (backend blueprint), a `$PORT`-aware
`backend/Dockerfile`, and `app/config.py` that auto-rewrites a bare
`postgres://` URL and accepts a comma-separated `CORS_ORIGINS`.

---

## 1. Database — Supabase (~3 min)

1. https://supabase.com → **New project**. Pick a region near you, set a DB
   password, wait for it to provision.
2. **Project Settings → Database → Connection string → URI**. Copy it. It looks
   like `postgres://postgres.xxxx:<password>@aws-0-...pooler.supabase.com:6543/postgres`.
   Use the **Transaction pooler** (port 6543) or the direct connection (5432) —
   either works.
3. That string is your `DATABASE_URL`. (No need to change `postgres://` → the
   backend rewrites it.)

PostGIS is already enabled on Supabase; the first migration's
`CREATE EXTENSION IF NOT EXISTS postgis` is a harmless no-op.

---

## 2. Backend — Render (~5 min)

1. Push this repo to GitHub (branch `main`).
2. https://render.com → **New → Blueprint** → connect the repo. Render reads
   `render.yaml` and proposes a service named **drishti-api**.
3. Before/after the first deploy, set these env vars (dashboard →
   drishti-api → **Environment**):
   - `DATABASE_URL` → the Supabase URI from step 1
   - `CORS_ORIGINS` → leave blank for now, fill in step 4
   - `LLM_API_KEY` → your Gemini key (optional — chat falls back without it)
   - `JWT_SECRET` is auto-generated by Render; leave it.
4. Deploy. The start command runs `alembic upgrade head` automatically, then
   `uvicorn … --workers 1`. Watch the logs until `Application startup complete`.
5. **Seed the demo data** — Render dashboard → drishti-api → **Shell**:
   ```
   python -m app.scripts.seed_demo_data
   ```
   (25 risk zones, 5 shelters, 5 responders, 2 demo alerts.)
6. Your API base URL is `https://drishti-api.onrender.com` (Render shows the
   real hostname). Check `https://drishti-api.onrender.com/api/v1/health`.

---

## 3. Frontend — Vercel (~3 min)

1. https://vercel.com → **Add New → Project** → import the same repo.
2. **Root Directory: `frontend`**. Framework preset auto-detects as Next.js.
3. **Environment Variables**:
   - `NEXT_PUBLIC_API_URL` → `https://drishti-api.onrender.com/api/v1`
     (your Render host + `/api/v1`)
   - `NEXT_PUBLIC_MAP_TILE_URL` → `https://tile.openstreetmap.org/{z}/{x}/{y}.png`
     (optional; this is the default)
4. Deploy. You'll get `https://drishti-xxxx.vercel.app`.

---

## 4. Wire CORS back to the frontend

Render → drishti-api → **Environment** → set:
```
CORS_ORIGINS = https://drishti-xxxx.vercel.app
```
Add the preview URL too if you want PR previews to work, comma-separated:
```
CORS_ORIGINS = https://drishti-xxxx.vercel.app,https://drishti-git-main-you.vercel.app
```
Save → Render redeploys. Done — open the Vercel URL.

---

## 5. Create a command-center login

Self-registration only makes citizens. Promote one via the API (any REST client):

```
# register a citizen first at /register in the UI, then in the Supabase
# SQL editor:
update users set role = 'admin' where phone = '<your phone>';
```
or, once you have one admin, use `POST /api/v1/users` for the rest.

---

## Known limits on the free tiers

- **Render free spins down after ~15 min idle** and cold-starts (~30–60 s) on
  the next request. Open SSE connections drop on spin-down; the frontend
  reconnects automatically. For an always-on demo, use Render's paid Starter
  plan, Railway, or Fly.io (same `startCommand`).
- **Uploaded evidence photos are on ephemeral disk** — they vanish on redeploy.
  Fine for a demo; for persistence, add a Render Disk or swap
  `app/services/storage.py` for Supabase Storage / S3.
- OpenStreetMap tiles are fine at demo traffic; heavy use needs a tile
  provider with an API key (set `NEXT_PUBLIC_MAP_TILE_URL`).

## Redeploys

- Push to `main` → Vercel and Render redeploy automatically.
- New migration → it runs on the next Render deploy (start command).
- Re-seed / wipe demo data → Render Shell: `python -m app.scripts.seed_demo_data --force`.
